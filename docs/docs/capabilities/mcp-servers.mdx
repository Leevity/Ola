# MCP 服务器 / MCP Servers

Ola 支持 Model Context Protocol (MCP)，用来把外部工具、资源和 prompts 接入 Agent。

## 配置存储 / Config storage

MCP 服务器配置会被写入：

```text
~/.ola/mcp-servers.json
```

主进程会在启动时自动连接所有 `enabled=true` 的 server。

## 支持的 transport / Supported transports

| transport         | 场景                |
| ----------------- | ------------------- |
| `stdio`           | 本地 CLI / 本地进程 |
| `sse`             | 远程 HTTP + SSE     |
| `streamable-http` | 新式 HTTP 传输      |

`streamable-http` 失败时还可以按配置回退到 `sse`。

## 主要 IPC / Main IPC

MCP 主进程 handler 提供这些能力：

- `mcp:list`
- `mcp:add`
- `mcp:update`
- `mcp:remove`
- `mcp:connect`
- `mcp:disconnect`
- `mcp:status`
- `mcp:server-info`
- `mcp:all-servers-info`
- `mcp:list-tools`
- `mcp:call-tool`
- `mcp:read-resource`
- `mcp:list-resources`
- `mcp:get-prompt`
- `mcp:list-prompts`
- `mcp:refresh-capabilities`

写操作 `mcp:add` / `mcp:update` / `mcp:remove` 一律返回 `{ success, error? }`：Main 会先校验曝光策略，
再用原子写落盘，所以 `success: false` 时磁盘上没有半个改动，调用方必须把它当成失败，不能先改自己的
列表。`mcp:server-info` 在没有活跃 client 时返回 `undefined`，设置面板据此清空缓存的 tools / exposedTools
/ resources / prompts，而不是继续显示上一次连接的能力。`capabilitiesTruncated` 为真表示能力发现在分页
上限处停止，面板列出的只是服务器宣告的一部分。

## 工具命名 / Tool naming

模型看到的 MCP 工具名由 `(toolAlias, 服务器宣告的名字)` 纯函数生成，Main、渲染进程和 runtime 三侧
得到完全相同的字符串：

```text
mcp__<toolAlias>__<sanitized name>          例：mcp__rea__binary_session
mcp__<toolAlias>__resource__<resource name> 例：mcp__docs__resource__notes_index
```

- `toolAlias` 在创建 server 时按不可变的 `id` 分配一次，之后不随 `name` 改名而变，历史 transcript 因此
  始终指向同一个工具。
- 整名上限 64 字符；段预算 = `64 - 5 - 2 - len(alias)`，超长的名字保留前缀并附加 `_<fnv1a32>` 尾巴，
  而不是截断，所以同前缀的两个长名字仍然可区分。
- server 的 resource 在两侧都注册成只读工具：渲染进程经 `mcp:read-resource`，Main 的 runtime 路径经
  `manager.readResource()`，两边使用同一个 `resource__` 段。
- 无法命名的工具不会被静默丢弃，而是带着 `INVALID_ALIAS` / `EMPTY_TOOL_NAME` / `TOO_LONG` 原因出现在
  `exposedTools` 里，设置面板把它列在 “Not exposable”。
- 上限：每个 server 最多暴露 `32` 个工具，单次 run 最多 `128` 个工具名。

## Server 配置 / Server config

`McpServerConfig` 常见字段：

| 字段                               | 作用                                |
| ---------------------------------- | ----------------------------------- |
| `id` / `name`                      | server 标识                         |
| `enabled`                          | 是否启用                            |
| `projectId`                        | 是否绑定到某个项目                  |
| `transport`                        | `stdio` / `sse` / `streamable-http` |
| `command` / `args` / `env` / `cwd` | stdio 进程配置                      |
| `url` / `headers`                  | HTTP/SSE 配置                       |
| `autoFallback`                     | streamable-http 失败后是否回退      |
| `description`                      | 说明                                |

## 能力发现 / Capability discovery

连接成功后，Ola 会把 server 暴露出来的：

- tools
- resources
- prompts

都整理到前端可用的列表里。Agent 就能像使用本地工具一样使用这些能力。

## 典型流程 / Typical flow

1. 在设置里新增 MCP server
2. 保存到 `mcp-servers.json`
3. 启动或手动连接 server
4. 读取工具 / 资源 / prompts
5. 在对话里直接调用
6. server 断开后，能力自动消失

## 示例 / Example

```json
{
  "id": "github",
  "name": "GitHub MCP",
  "enabled": true,
  "transport": "stdio",
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": {
    "GITHUB_PERSONAL_ACCESS_TOKEN": "..."
  }
}
```

## 什么时候该用 MCP？ / When to use MCP?

- 访问外部系统 API
- 读写第三方资源
- 把 CLI 工具接进 Agent
- 想把团队内部服务暴露成可调用能力
