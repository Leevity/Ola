# 聊天模式 / Chat Modes

Ola 的模式系统不只是“语气不同”，而是**工具权限、提示词目标和工作方式**都不同。当前模式包括：`chat`、`clarify` 和 `execute`。

## 模式总览 / Mode overview

| 模式      | 定位     | 典型行为                                       |
| --------- | -------- | ---------------------------------------------- |
| `chat`    | 轻量对话 | 直接回答、少工具、快速互动                     |
| `clarify` | 需求澄清 | 先问清楚，再进入 Plan Mode                     |
| `execute` | 执行     | 读写文件、跑 Shell、检索资料、调用已连接的集成 |

早期的 `cowork`、`code` 和 `acp` 已并入 `execute`。旧会话以 `execute` 打开，消息与历史不受影响。

## Chat

Chat 是最轻量的对话模式。它适合：

- 日常问答
- 快速解释
- 不需要复杂工具的请求

它的目标是“先把话说清楚”，不是“先把工作做完”。

## Clarify

Clarify 模式的目标是把不清晰的需求变成可执行计划：

1. 先读取上下文
2. 再通过 `AskUserQuestion` 追问关键歧义
3. 最后进入 [Plan Mode](/docs/capabilities/plan-mode)

它适合：

- 需求不完整
- 方案有多个分支
- 风险和约束还没确认

## Execute

Execute 是执行模式，覆盖从代码到文档、运维和已连接应用的动手工作：

- 读写项目文件
- 搜索实现
- 跑 Shell 命令
- 修 bug / 加功能 / 重构
- 汇总资料、操作已连接的集成

如果你要让 Agent 修改仓库，优先用 Execute，并且尽量先设置 working folder。

如果需要“只设计、不直接改代码”，可以在会话里挂上团队：主 Agent 会转为架构控制角色，先澄清边界，再通过子 Agent 和团队成员分派实现。

## 模式和 Plan Mode 的关系 / Relation to Plan Mode

- Clarify 常常会把你引导到 Plan Mode
- Execute 模式下也可以进入 Plan Mode
- 挂着团队的 Execute 会话先设计再委派，通常不会直接写代码
- Plan Mode 是一个独立的执行前审阅阶段，不等同于模式切换

## 你可以怎么选 / How to choose

- **先聊天**：Chat
- **先问清楚**：Clarify
- **动手做事**：Execute
- **设计和委派**：Execute + 团队
