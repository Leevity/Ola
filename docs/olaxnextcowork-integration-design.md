# Ola 工作台体验集成改造方案（含功能设计）

## 1. 目标与范围

本方案把工作台效率功能融入 Ola 现有 Electron + React + TypeScript 架构。功能优先满足日常会话、代码工作区与扩展视图的连贯操作；原有首页、会话页面和设置入口保持默认行为，新增体验按需出现。改造按可交付批次推进，每项都给出用户流程和验收条件。

## 2. 用户角色与主要任务

| 角色            | 主要任务                                 | 体验要求                                         |
| --------------- | ---------------------------------------- | ------------------------------------------------ |
| 日常使用者      | 新建/切换会话、查找命令、恢复待发送消息  | 键盘可达、状态明确、重启后不丢待处理内容         |
| 开发者          | 在项目中查看代码、使用终端、调整面板布局 | 终端位置可切换，项目间布局互不覆盖               |
| 管理员/扩展作者 | 安装或启停扩展，提供工作台命令和只读视图 | 能发现扩展贡献，权限边界清晰，禁用后立即撤销入口 |

## 3. 功能设计

### F1. 工作台命令中心

**入口**：现有命令面板；键盘快捷键帮助页作为同一命令目录的第二个展示入口。扩展注册的命令也出现在命令面板。

**交互流程**：

1. 用户打开命令面板并输入名称或关键词。
2. 系统按命令名称、描述、关键词过滤，并按功能分组显示。
3. 每项显示快捷键（若有）和可用状态；不可用项说明所需上下文。
4. 用户选择后执行对应动作；扩展命令打开隔离的扩展视图。

**状态与规则**：命令 ID 全局唯一；扩展命令使用 `extension.<extensionId>.<commandName>` 命名空间。仅启用且加载成功的扩展贡献命令。扩展卸载、禁用或刷新后，命令立即撤销。帮助页只展示当前已注册且可见的快捷键，避免帮助文本与实际行为不一致。

**验收**：内置命令可搜索并执行；快捷键帮助与注册表一致；重复 ID 被拒绝/跳过且有诊断；停用扩展后命令不再出现。

### F2. 会话待发送队列与崩溃恢复

**入口**：聊天输入框发送期间，后续消息进入队列；输入框上方显示队列数量和每条消息状态。

**交互流程**：

1. 当前会话正在生成时，用户继续发送消息，消息加入该会话队列并持久化。
2. 当前生成完成后，队列按顺序逐条发送。
3. 应用重启后，队列恢复到原会话并暂停；用户检查恢复条目后点击“继续”逐条发送。
4. 如果应用在发送边界中退出，该条显示“发送状态待确认”，用户检查后选择重试或删除，避免无提示重复发送。
5. 发送失败时保留消息并暂停队列，用户可重试、编辑或移除。

**状态**：`queued`、`dispatching`、`needs_review`。持久化边界包含会话 ID、工作空间 ID、消息文本/图片/发送选项、创建时间和恢复标记。每会话最多 50 条；队列写入失败时不静默接受排队操作。

**验收**：切换会话不会串队列；重启恢复后不自动发送；发送中途退出的条目标记待确认；失败、移除、清空后 UI 与数据库一致；队列超限和损坏数据被拒绝或安全裁剪。

### F3. 工作空间与会话双层标签

**入口**：工作台顶部显示工作空间标签；其下沿用现有会话标签。

**交互流程**：用户先切换个人/团队工作空间，再从当前空间的会话标签切换会话。键盘左右方向可切换同层标签。切换空间后，仅显示属于目标空间且当前仍存在的会话。

**状态与规则**：会话标签继续遵守窗口/工作空间隔离。单工作空间时不额外显示工作空间条，保持现有首屏密度。异步加载旧空间结果不能覆盖新空间状态。

**验收**：单空间布局无额外空条；多空间时可见并可键盘切换；切换后无跨空间会话；关闭/删除会话后标签列表与选择状态稳定。

### F4. 项目终端停靠位置

**入口**：代码工作区终端标题栏新增“移至右侧/移至底部”按钮。

**交互流程**：用户在底部终端与右侧终端之间切换；工作目录/终端进程状态保留，工作区布局按项目保存。右侧终端占用受限宽度，底部终端保留现有拖动高度调整。工作区过窄时自动回到底部布局，并提示扩大工作区后才能启用右侧停靠；窗口变宽时按项目偏好恢复右侧布局。

**状态与规则**：默认仍为底部；每个项目独立记忆停靠位置。现有会话内终端继续使用底部模式，不展示无效移动按钮。

**验收**：切换停靠位置不丢终端会话；重启后按项目恢复；项目 A 的位置不影响项目 B；右侧停靠时主编辑区至少保留 220px，终端至少保留 180px；窄窗口自动回到底部并禁用右侧停靠入口，窗口变宽后按偏好恢复；不得压缩主内容区。

### F5. 扩展工作台视图

**入口**：扩展可在清单中声明静态视图与对应命令；命令中心选择命令后打开视图对话框。扩展管理页展示每个扩展贡献的命令/视图。

**交互流程**：启用扩展 → 校验清单 → 注册命令 → 用户从命令中心打开视图 → 关闭视图返回当前工作区。禁用扩展后相关命令/视图入口撤销。

**安全规则**：扩展视图以无脚本 sandbox iframe 加载；CSP 禁止脚本、网络、表单提交、弹窗和对象嵌入。扩展 HTML 资产限制为 8 MiB。V1 只提供静态 HTML 展示，不开放 Node、文件、Shell 或任意 JS 执行。

**验收**：旧扩展清单仍可正常加载；无效/越界视图路径拒绝；启停后贡献刷新正确；视图加载失败时展示可理解错误；父页面和本地数据不可被扩展内容读取。

## 4. 页面结构与交互约定

```text
应用工作台
├── 工作空间标签（仅多空间显示）
├── 会话标签（当前工作空间内）
├── 主内容区
│   ├── 会话 / 代码工作区
│   └── 可停靠终端（代码工作区）
├── 命令中心（全局覆盖层）
├── 扩展视图（隔离对话框）
└── 待发送队列（聊天输入区内联）
```

键盘操作需可见、可撤销，不用仅颜色表达状态；队列发送、恢复确认和失败状态使用明确文本。所有新文案走 i18n，不在组件中写死中文。

### 4.1 页面级功能设计

| 页面/区域          | 页面组成                                                     | 用户操作                                                  | 状态与反馈                                                                                                               |
| ------------------ | ------------------------------------------------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 命令中心           | 搜索框、分组命令列表、快捷键提示、上下文不可用说明           | 输入关键词过滤；方向键移动；Enter 执行；Esc 关闭          | 无结果显示可清除的空结果提示；不可用命令说明缺少的上下文；扩展被停用后立即从列表移除                                     |
| 会话待发送队列     | 输入框上方队列摘要、逐条消息卡片、发送状态和单条操作         | 生成期间继续排队；查看/编辑/重试/删除；重启后逐条确认继续 | queued 显示排队序号；dispatching 显示发送中；needs_review 提醒用户核对后重试或删除；数据库写入失败时提示并保留输入框内容 |
| 工作空间与会话标签 | 多空间时显示空间层；当前空间会话层显示标题、选择态和关闭入口 | 点击或键盘切换空间/会话；关闭会话；新建会话               | 加载目标空间时保留明确加载态；异步旧结果不得覆盖当前空间；空空间展示创建会话入口                                         |
| 代码工作区终端     | 编辑器主区、终端面板、底部/右侧停靠切换、拖动分隔区          | 切换停靠；调整面板尺寸；关闭/重开终端                     | 切换位置保留正在运行的进程；过窄时明确回落到底部；右侧最小宽度不满足时禁用入口并给出提示                                 |
| 扩展工作台视图     | 扩展提供的静态 HTML 内容、标题、关闭按钮、加载失败提示       | 从命令中心打开；关闭返回原工作区；管理员停用扩展          | 加载失败显示本地化且不暴露路径/内部异常；扩展停用立即关闭该扩展视图并撤销命令                                            |

### 4.2 关键业务规则

1. **队列归属**：队列主键由工作空间和会话共同确定。切换标签只切换可见队列，不迁移或复用其他会话的消息；进程重启后按相同归属恢复。
2. **恢复安全**：持久化条目在启动时一律暂停。处于发送边界的条目标记为待确认，不自动重放，用户确认后才允许再次发送。
3. **终端偏好**：停靠位置按项目保存；当前可用宽度不足时只改变临时布局，不覆盖项目偏好，空间恢复后重新应用偏好。
4. **扩展撤销**：扩展贡献以当前启用状态为准。停用、移除或项目授权撤销后，已打开视图关闭，命令执行再次校验来源状态。
5. **无障碍与本地化**：所有状态除颜色外还必须有文本或图标语义；命令列表可键盘操作；新增文案进入 i18n 资源，不在组件内硬编码。

每批次通过类型检查、相关行为测试、定向 lint，并进行 Electron 界面冒烟。P0 要验证应用强制退出/重启后的队列人工恢复；P1 要验证双空间和两个项目的布局隔离；P2 要验证静态视图攻击面约束和扩展禁用后的撤销。若某项只能在真实 Electron 或平台环境验证，应明确列为未完成证据，不能以单测代替。
