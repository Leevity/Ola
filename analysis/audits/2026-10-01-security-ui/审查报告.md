# Ola 安全与 UI 审查（2026-10-01）

## 范围与方法

- 代码：Electron 主窗口、Preload、IPC 工作区边界、浏览器/文档预览、设置导航及相关中文资源。
- 界面：隔离数据根目录启动当前构建；采集工作台、通用设置、权限、插件、最小设置窗口，以及会话队列、独立窗口和项目终端截图。
- 验证：`npx electron-vite build` 成功；`npm run verify:pending-session-queue-electron` 1/1 通过。隔离导航探针仅访问本机临时 HTTP 页面，未调用任何敏感 IPC，也未读取真实用户数据。
- 限制：未做依赖漏洞扫描、渗透测试、真实账户/远端服务测试，也未完成屏幕阅读器和键盘全流程测试。截图显示的是隔离测试数据，不代表真实账户配置。

## 结论

**安全优先级最高的是主窗口导航与 Preload 暴露形成的组合风险。** 本机隔离探针证明：主应用窗口能从 Ola 页面导航到普通 HTTP 页面，该页面仍取得 `window.ola`，且 `window.electron.ipcRenderer.invoke` 是函数。应先封闭此路径，再处理其他 UI 工作。

设置页导航图标已使用不同的 Lucide 图标，未重现“多项完全一致”。但中文模式的工作台引导和插件生命周期模块出现英文回退；设置导航和辅助文字使用 10–13px CSS 字号，层级偏弱。最窄会话布局中的运行状态浮层遮挡队列操作。

## 安全发现

### S1 · 严重：普通网页可在主应用窗口获得 IPC Bridge

- **证据**：`src/main/index.ts:1243-1315` 的 `configureAppWindow` 限制了 `webview` 附加与新窗口，却没有主窗口的 `will-navigate` / `will-frame-navigate` 阻止规则。`src/renderer/src/lib/preview/viewers/docx-viewer.tsx:45,118` 允许渲染带 `href` 的文档链接，没有在预览中接管点击。`src/preload/index.ts:108-110` 将 bridge 注入当前页面。
- **运行验证**：`security-navigation-probe.json` 记录普通本机 HTTP 页面的 `preload: "object"` 和 `unrestrictedIpc: "function"`。这是边界验证，未执行实际敏感操作。
- **影响**：用户点击不可信文档中的网页链接等导航入口后，目标网页可能在同一窗口使用 Ola 的本地 IPC 能力；文件、命令、扩展等能力取决于具体 handler。
- **修复**：主窗口只允许已打包应用 URL（开发时仅精确的本地开发服务器 origin）顶层导航；合法网页链接交给系统浏览器或内置隔离浏览器。敏感 IPC handler 还需验证发送 frame 的 URL/origin，避免单点导航拦截失效。

### S2 · 高：Preload 的严格 IPC 白名单可被通用 API 绕过

- **证据**：`src/preload/index.ts:14-25` 设定了生产环境白名单，但 `src/preload/index.ts:109` 同时暴露 `@electron-toolkit/preload` 的 `electronAPI`。该依赖实际导出通用 `ipcRenderer.invoke/send/sendSync`，不调用 `validateIpcChannel`。
- **影响**：拿到页面脚本执行权的内容可以绕过预加载层的通道检查，并直接访问主进程已注册的通道。S1 已证明普通导航页可以拿到这条入口。
- **修复**：移除通用 `electronAPI` 暴露；确有需要的缩放、环境信息等操作应各自封装成窄接口。主进程 handler 自身也要校验发送者，不能把 Preload 白名单当最终授权。

### S3 · 中：部分数据库 IPC 只校验工作区存在，未绑定发送窗口

- **证据**：`src/main/ipc/db-handlers.ts:333-364` 的 `requireDbWorkspace` 仅调用 `authorizeDbWorkspace(workspaceId, loadOfflineWorkspaceIds)`；`src/main/ipc/db-workspace-authorization.ts:1-15` 只确认工作区 ID 在可用集合中。列表、读取、创建等处理器没有使用 `event.sender` 对照窗口已注册工作区。
- **影响**：同一应用中的窗口若能调用其他已知工作区 ID，可越过窗口级工作区隔离读取或写入其数据。是否构成跨用户边界取决于多工作区/账户使用方式，但当前窗口隔离承诺未被 DB 层执行。
- **修复**：把 `event` 传入统一的 DB 授权函数，要求主 frame、受信应用 URL、注册窗口工作区与请求工作区一致；为独立窗口和切换工作区补回归检查。

## UI 与可访问性发现

### U1 · 中：中文界面有整块英文回退

- **截图**：`01-workspace.png`、`04-settings-integrations.png`。
- **代码**：`src/renderer/src/components/chat/FirstSuccessPanel.tsx:25-111` 的 `firstSuccess.*` 未见于中文 `chat.json`；`src/renderer/src/components/settings/CapabilityCenterPanel.tsx:39-77` 新增生命周期字段，但中文 `settings.json` 对应对象缺这些键。
- **影响**：中文模式下新手路径、能力状态同时出现英文，降低扫描和理解效率。
- **修复**：补齐中英文资源键并让缺键检查覆盖新增模块；把状态 ID 与展示文案分开，不以 `defaultValue` 英文作为发布文案。

### U2 · 中：辅助字号和对比层级偏弱

- **截图**：`02-settings-general.png`、`04-settings-integrations.png`、`05-settings-narrow.png`、`01-workspace.png`。
- **代码**：`src/renderer/src/components/settings/SettingsPage.tsx:3410-3446` 的分组标签 11px、导航项 13px；`src/renderer/src/components/settings/CapabilityCenterPanel.tsx:39-80` 的说明和状态 10–11px；`src/renderer/src/components/chat/FirstSuccessPanel.tsx:73-111` 的任务解释和动作 10px。部分次级文字还叠加较低透明度。
- **影响**：在中文密集设置项和窄窗口下，说明、状态与动作不易区分。截图只能确认视觉风险，不能据此判定 WCAG 对比度是否合格。
- **修复**：设置侧导航至少 14px、分组至少 12px、正文说明至少 13–14px；对重要状态减少透明度。先统一组件级字号层级，再逐页收敛局部 `text-[10px]`。

### U3 · 中：窄会话中的状态浮层遮挡队列

- **截图**：`queue-minimum-window.png`。760×560 的隔离验收截图中，状态浮层覆盖右侧会话内容与队列操作附近区域。
- **代码**：`src/renderer/src/components/layout/RuntimeStatusPanel.tsx:450-459` 使用右上角绝对定位，宽度最多 320px；在窄主内容区占比较高。
- **修复**：窄窗口改为可关闭的抽屉或占位面板；打开时保留队列操作的可见区域，并确保 Esc、焦点返回和滚动行为明确。

### U4 · 低：插件页 tab 语义与键盘行为不完整

- **截图**：`04-settings-integrations.png`。
- **代码**：`src/renderer/src/components/settings/CapabilityCenterPanel.tsx:86-111` 设置 `tablist`、`tab`、`aria-selected`，但没有左右方向键切换、焦点管理和 tab 与面板的关联 ID。
- **修复**：补齐 roving `tabIndex`、方向键/Home/End 操作及 `aria-controls` / `aria-labelledby`，或使用现有 Tabs 组件。

## 建议顺序与完成标准

1. **P0 安全封口**：主窗口拒绝离开应用 origin；移除通用 `electronAPI`；高危 IPC 加主 frame + origin 校验。隔离环境中复跑导航探针，应看到导航被拒或外部浏览器接管，普通网页拿不到 bridge。
2. **P1 工作区授权**：DB IPC 以发送窗口工作区判权；多窗口跨工作区读写请求均拒绝，同工作区正常工作。
3. **P1 中文体验**：补 `firstSuccess` 与生命周期资源，中文模式 8 个审查步骤中不再出现非专有名词的英文回退。
4. **P2 字体与窄窗口**：统一字号、提高次级文案可读性，重做窄会话状态浮层；在 900×600 设置页与 760×560 会话页复看截图，并做键盘/读屏检查。

本审查发现的问题已按优先级完成整改。逐项实施内容和验收状态见[整改验收.md](./整改验收.md)；截图和探针结果保存在本目录。
