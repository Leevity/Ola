# Ola Windows 功能交付与手动验收清单

## 本轮范围调整

2026-10-04 用户明确调整分工：先完成 M0–M4 功能代码及 Windows 本机验证，高复杂度场景由用户手动验收后反馈，再修复。macOS/Linux 与 Windows arm64 原生验收移出本轮完成条件，原跨平台迁移台账保留历史事实，不伪造通过状态。M5 不纳入本轮。

开发完成率暂估约 85%，合理估算区间 80%–90%。依据为 M1 主体实现、M2 基础闭环、M3 三模板与预检查、M4 调度投递保护已接入，但多来源结果和能力级恢复仍需补齐。这是工程估算，不是逐项审计计数；旧 9/20 的 45% 仅表示跨平台严格退出台账通过率。后续开发状态和手动签收分别记录，不能把待手测写成未开发，也不能把已有代码写成体验已通过。

## 之前的具体卡点

1. 六平台原生安装、升级和启动被计入总完成条件，当前机器只能原生验证 Windows x64。
2. 真实主站个人/团队账号、授权撤销及流式调用，真实 SSH 与消息渠道缺少可控环境。
3. 真实旧版数据升级需要独立 Windows 用户或虚拟机。旧版可能忽略目录环境覆盖，不宜直接用当前真实用户配置运行。
4. 原生缩放、中文输入法、跨时区旧日期、长时间休眠恢复和新用户任务，自动化无法替代实际呈现与人工确认。
5. 大项必须所有子条件通过才改变状态，局部修复没有体现在旧百分比中。

## 开发及本机验证顺序

1. 完善 SSH Bash、MCP、媒体等来源的结构化结果协议；缺少合同的来源明确保留不支持状态。
2. 核对结果预览、复制、后续输入与失效文件提示，保留来源和空间授权。
3. 核对审批、取消、失败草稿恢复和多窗口刷新，修复可复现代码问题。
4. 补模板条件修复入口、能力状态错误提示、Cron 页面操作反馈。
5. Windows 类型检查、受影响行为测试、生产构建和可控桌面流程，记录版本与剩余边界。

## 交给用户的手动验收

| 场景       | 操作                                                                     | 应看到的结果                                             |
| ---------- | ------------------------------------------------------------------------ | -------------------------------------------------------- |
| 设置呈现   | 100%/125%/150% 系统缩放，逐个设置子页，缩小窗口并用中文输入法            | 字号有层级、中文不截断、控件可点击、候选词确认不误发送   |
| 双窗口运行 | 主窗口和独立窗口打开同一会话，运行中删除；另一轮模拟删除失败后重试       | 实际运行停止后才删除；失败保留会话；两窗口最终一致       |
| 结果复用   | 用真实模型生成文件，从结果中心预览、复制、引用到下一次请求；移动文件再试 | 来源可追溯、有效文件可复用、失效文件明确提示、原草稿保留 |
| 三模板     | 项目体检、资料报告、SSH 巡检；分别缺模型/目录/连接再恢复                 | 缺项有准确原因与入口；真实执行后可找到运行和结果         |
| Cron 交付  | 用测试渠道分别成功、失败、超时，人工核对后重试                           | 执行与投递分开；未知不自动重发；重试不重新执行 Agent     |
| 退出与休眠 | 计划到期时退出/休眠，恢复后观察；切换系统时区                            | 行为符合页面说明，不逐次补发错过的周期                   |
| 真实旧数据 | 独立 Windows 用户下旧版建立会话/项目/设置，再安装新版                    | 数据完整、备份可恢复、凭据可用、权限正常                 |
| 真实主站   | 测试个人/团队账号，授权、流式请求、撤销、切换空间                        | 撤销后调用被拒绝，空间数据与凭据不串用                   |

反馈请包含应用版本、操作步骤、期望与实际结果、截图及脱敏日志；无需提供密码或令牌。用户尚未签收的条目保持“待手动验收”。

## 本轮代码切片

SSH Bash 增加 outputFiles 声明，限制为最多 16 个远程绝对路径。执行前后用已授权 SFTP 元数据确认文件新增/变化；退出码非零、超时、文件缺失或未确认变化时不登记；统一结果登记前再次确认文件存在。SFTP 修改时间可能只有秒级，同尺寸且时间未变化的覆盖无法确认，会保守地不收集结果。真实 SSH 和 UI 呈现待用户手测。
