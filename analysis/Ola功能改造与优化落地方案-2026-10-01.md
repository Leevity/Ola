# Ola 功能改造与优化落地方案

日期：2026-10-02｜版本：1.2。依据《Ola 功能全景与产品路线图》及《Ola 功能改造实施进度》。适用范围是当前 Electron、React、TypeScript、Main、Preload、Renderer、Runtime 架构。本文是功能设计、开发拆分与验收清单；“已接入”不等于真实环境完成验收。

## 1. 交付目标与边界

目标是让用户完成一条可追溯的工作链：**选择项目和场景 → 检查条件 → 创建任务 → 执行与审批 → 查看结果 → 处理失败 → 再次使用**。日常工作与开发工作共用工作空间、运行记录、结果、能力检查和权限控制。保留现有页面、BusinessRepository、Run Journal 和 TS Runtime，不另建任务表或调度器。

首批交付范围为 M0–M4。M5 的项目经验、团队模板和用量预算在有真实使用证据后再排期。发布证据线 G 与 M1 起并行准备，产品功能验收和跨平台发布验收分别签收。

当前执行结论以《Ola 功能改造实施进度》为准。截至 2026-10-02，若按“代码切片、自动化回归、桌面端验收、真实环境验收”分层：

## 3. 功能与数据契约

### 3.1 任务、运行、结果

1. **任务**由 BusinessRepository 持久化，现有七状态为 pending、in_progress、in_review、blocked、completed、failed、cancelled。`in_review` 是已有的待审核状态；此前方案误写的 `ready` 并非持久化状态，不能据此改写旧任务。所有创建、编辑、删除等操作等待写入确认；保存失败保留用户输入并允许重试。任务日期采用 `YYYY-MM-DD` 日历日，旧时间戳只读兼容；不推测旧记录的原始录入时区。
2. **运行**由 Run Journal 持久化，以 `runId + workspaceId` 定位一次尝试。运行保存来源、会话、项目快照、可选业务任务 ID/名称、开始与结束时间、状态和事件。重试创建新 runId，并显式记录来源 runId；不覆盖原结果。Task completed 与 Run succeeded 是不同事实。
3. **结果**只由已确认成功的生产工具登记。索引至少包含 artifactId、workspaceId、projectId、runId、类型、位置、标题、创建时间、来源工具、存在状态。文件以规范化绝对路径登记；URL 以结构化字段登记且不自动抓取。Shell、媒体、MCP 与扩展需各自返回结构化结果协议，不能靠扫描文本猜测路径或 URL。
4. **权限**在 Renderer、Preload、Main 与 Runtime 的每个边界传递并校验 workspaceId。Main 在异步调用前后都核对窗口所属空间；projectId 必须属于该空间。列表查询必须分页，路径预览和文件删除沿用已有安全 IPC，不从结果索引直接放开任意文件操作。
5. **存储升级**采用版本化迁移。旧数据只按可核验的事件补结果索引；不能把历史工具输入、失败输出或任意 Shell 文本追认成成功产物。删除索引默认不删文件，实际删除另设明确操作和确认。

### 3.2 运行状态与动作

统一展示为排队、执行中、等待审批、等待用户、成功、失败、取消、中断待确认。UI 从真实 Runtime/Cron 状态映射；通知、聊天和运行页使用同一运行投影。取消请求后先显示“取消中”，收到终态后再确定结果。审批链接到具体 run 与 toolCall，过期审批不可再次生效。失败运行的首个安全恢复入口只把原请求放回来源会话草稿，绝不自动重放；目标会话已有未发送草稿时保留原内容。用户提交前须检查文件变更、远程写入、消息发送等副作用。只有能证明工具调用幂等或用户确认副作用结果后，才考虑直接创建新 attempt；该草稿入口不等同于完整自动重试功能。

### 3.3 场景模板

模板结构：ID、版本、名称、输入 schema、所需能力、权限等级、默认输出位置、预期结果与执行配置。V1 仅包含项目只读体检、资料整理成报告、SSH 只读巡检。预检查验证模型绑定、目录可读写、连接/授权、所需 Skill 与工具可用性；仅展示条件，不发起昂贵模型调用或外部副作用。用户保存的是参数副本和模板版本，升级模板不能覆盖历史参数。

### 3.4 Cron 交付

一次定时触发生成独立 run 与 delivery 记录。调度、执行、投递分别写状态、时间、错误码和重试次数。投递失败时只重试投递，使用稳定 deliveryId/幂等键；若渠道无法确认是否已发送，标为“结果待核对”，不自动重发。重试必须复用原目标快照，用户确认/编辑待发送文本，不重新执行 Agent；旧记录没有目标快照时不给重试入口。试运行按原提示词执行只读预览，仅开放 Read/LS/Glob/Grep，不开放 Write/Edit/Bash、渠道/通知工具，不传递目标会话，不创建投递记录；运行结果持久保存并标记 runKind=trial，不增加 fire_count、不移动 last_fired_at、不消耗一次性计划，也可在计划停用时启动。手动立即运行记录 runKind=manual，不改变自动调度计数；定时触发记录 runKind=scheduled 并保持原计数语义。编辑页对每种计划明确展示生效时区、应用退出/休眠期间的处理规则、禁用后行为和“立即运行”例外：手动操作是显式用户动作，允许对已停用任务执行；停用只阻止后续自动触发。一次性计划若到期时应用未运行，恢复后标记过期并跳过，不补发；重复计划不追赶错过的每个周期，只从当前调度边界继续。禁用与定时回调竞争时，Main 重读 BusinessRepository 当前记录并在写入 run 前复核 enabled/deleted 状态。

## 8. 功能改造蓝图：从入口到交付

本节把路线图的 R1–R8 展开成可实现的用户流程。首批只做 M0–M4 中已排定的任务，不另建平行导航、任务表或运行引擎；每个功能按“入口、输入、处理、结果、异常、权限、验收”实现。页面名称可在开发前做一次术语统一，但不能因此扩大业务范围。

### 8.1 工作台与新手首个成功

**目标用户任务：** 用户打开 Ola 后，知道从哪里开始、当前配置是否能完成任务，并能拿到一个可复用结果。

**页面组成：** 当前空间/项目选择；继续最近会话；最近运行；需要处理数量；三个已定义场景模板。首页不显示未经验证的健康绿灯，也不把固定导航卡当作“已就绪”。

**流程：** 选模板 → 填写/确认输入范围 → 前置检查 → 缺项时显示原因和配置直达链接 → 生成执行草稿 → 用户审阅并发送 → 运行详情跟踪 → 结果入索引 → 可返回项目/会话复用。模板只保存版本化参数副本；运行前再次检查空间、资源和权限，不能依赖首页缓存的检查结论。

**异常与验收：** 无模型、目录不存在/不可读、Skill/MCP 未启用或 SSH 不可连接时，指出具体缺项并保留已填写参数；取消前置检查不产生 Run；首次真实执行必须能在运行记录找到对应结果。M3 模板先以只读项目体检、资料整理报告、SSH 只读巡检为限。

### 8.2 任务与执行中心

**对象边界：** 业务任务表示“要完成的工作”；Run 表示一次执行尝试；审批表示一次具体工具调用的授权；Delivery 表示一次外部投递尝试；Artifact 表示可复用结果。它们通过稳定 ID 关联，但各自保留状态和生命周期。

**流程：** 创建/编辑任务 → 持久化确认 → 从任务启动会话运行或手动跟踪 → 运行列表按来源、状态、空间、时间筛选 → 进入详情查看步骤/审批/错误/结果 → 取消、回会话、核对或安全恢复。运行中心统一展示会话、Cron、渠道、Team 来源；来源暂不可查询时显示部分数据源错误，不将错误伪装为空结果。

**列表与详情：** 列表显示名称、来源、项目、状态、时间、耗时及待处理原因；分页游标稳定且新记录不导致翻页重复/遗漏。详情显示快照而非依赖当前可变任务名称；历史任务被删除后仍能辨认来源。任务完成不自动等价于 Run 成功，Run 成功也不自动将业务任务标为完成。

**动作规则：** 取消是请求态直到 Runtime 确认终态；审批绑定 runId/toolCallId 且只能对仍有效的待批请求生效；失败恢复首先仅准备原始文本草稿，不自动重跑。涉及文件、Shell、SSH、消息等副作用时要求用户复核；消息投递只允许对明确失败且目标快照完整的尝试做独立重发。

**验收：** 同一 run 在任务页、会话和通知中的状态一致；重启后可定位详情；空间切换不可读到另一空间记录；真实失败、取消、审批过期与翻页并发均有证据。

### 8.3 结果中心与项目复用

**入口：** 任务/自动化页提供跨项目结果搜索；项目主页提供当前项目结果；运行详情提供本次运行结果。三处查询同一索引服务，默认继承当前空间和项目边界。

**结果卡：** 类型、名称、创建时间、来源运行/会话、可用状态；文件显示预览/打开位置，文本类支持复制，均可追溯来源。丢失文件显示已移动或删除；移除结果只隐藏索引，不删除源文件。下一次输入会校验目标会话和文件存在性，保留草稿原文、附件与 Skill，避免重复引用。

**接入策略：** 文件写入、声明式本地 Shell 文件和图片生成使用结构化登记协议；SSH、视频/音频、MCP、扩展由各自提供者声明资源类型、来源和可验证位置后再接入。失败调用、日志中的路径字符串、任意 URL 和未确认外部资源均不能自动登记。查询按时间与 ID 稳定分页。

**验收：** 逐种来源验证成功/失败、越权、文件不存在、索引移除、重启查询、再次输入及跨空间拒绝。没有协议的来源在 UI 明示暂不支持统一结果收集，不猜测内容。

### 8.4 能力中心与可诊断性

将 Provider、Skills、MCP、内置插件、Extensions、消息渠道按同一用户任务表达为：已安装 → 已启用 → 已配置 → 已授权/连接 → 最近检查/调用 → 可修复动作。能力成熟度（GA/Beta）与当前连接健康分开显示；“未检测”不是健康，“启用”不代表运行正常。

用户主动刷新后才触发状态检查；状态失败与空配置分开。每项检查展示检查时间、影响范围、可执行的修复入口。诊断导出采用字段 allowlist，排除令牌、密钥、Cookie、用户内容、目标 ID、绝对路径和原始错误正文。真实连通性测试需用户发起，并说明是否会产生外部请求。

**验收：** 无凭据、凭据失效、网络不可达、服务停用、配置未完成分别呈现；导出做敏感字段回归；状态查询不得暗中启动服务或发送消息。

### 8.5 Cron 自动化交付

编辑时先选择单次/间隔/Cron，再配置提示词、工作空间、项目、模型/工具、输出位置、交付渠道及收件会话；对时区和应用退出/休眠时漏跑行为就地说明。保存后可试运行；预览结果由用户确认是否启用计划。

运行详情分开呈现调度、Agent 执行、结果生成、消息投递。执行成功但投递失败时保留产物并只处理投递；外部结果不确定时暂停自动重试，要求人工核对。试运行开放只读能力、不投递、不改计划计数；手动立即运行和计划触发分别标记来源。停用计划阻止自动触发，但不吞掉用户显式的立即运行操作。

**验收：** 跨时区/DST、停用竞态、应用退出漏跑、重复回调、渠道成功/失败/未知、重启恢复 pending、重试链去重和人工核对均有独立场景；成功发送只发生一次，未知结果不盲目重发。

### 8.6 项目、会话与能力生态的边界优化

本轮将空间/项目/会话作为已有主干，不进行整体重做。项目负责材料和产物归属，会话保存上下文，任务跟踪业务进度，运行保存尝试。切换空间时所有列表、缓存、订阅与待处理动作都重新校验；打开独立窗口时保留项目/终端等偏好，但资源不存在或空间无权限时安全回退。

Skills、MCP、插件、扩展仍保留各自安装和配置页；统一搜索与能力状态入口负责发现和诊断，不将异质能力强行合并成一个配置表单。SSH 与远程桌面明确区分，远程写操作继续要求相应授权。模型与账户显示已配置/未检测/可用/失效及最近检查时间，不以静态默认值显示可用。

### 8.7 安全、数据与运维横切要求

所有新增 IPC 采用显式 channel allowlist、可信 frame 检查和按窗口 workspace 授权；Renderer 传入的 workspaceId/projectId 不能自行决定授权。文件路径规范化后验证边界，外部 URL 做协议/来源校验。凭据只通过现有安全存储和最小权限接口传递，日志与诊断默认脱敏。

业务表和 Run Journal 采用独立、版本化迁移；记录迁移前备份、升级校验和可恢复策略。分页查询必须有上界；跨窗口缓存要能按 workspace/version 失效；异步请求按 requestId 避免旧结果覆盖新空间。安全/数据问题作为每张功能卡的验收项，而非最终阶段补做。

## 9. 成功指标与验收看板

上线前建立基线；没有埋点/真实样本时先用手工验收统计，不为了指标临时收集用户内容。所有比例注明样本数、版本、平台和观察周期。

| 指标           | 定义                                                       | 第一阶段目标/判定                                       |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------------- |
| 任务保存可信度 | 用户确认成功的修改，重启后仍存在的比例                     | 验收样本 100%；任何丢失或假成功为阻断                   |
| 首次任务完成率 | 新用户启动模板后获得可查看结果的会话比例                   | 三个模板分别记录分母/失败原因；先形成基线，再设提升目标 |
| 可追溯运行率   | 列表运行能打开来源/详情并准确区分状态的比例                | 覆盖每种来源的验收样本 100%；不完整来源明确报错         |
| 结果复用成功率 | 从结果入口引用后，目标会话能读取有效资源的比例             | 支持的来源样本 100%；失效文件明确拦截                   |
| 处理时间       | 从出现 failed/approval/delivery attention 到完成处理的时间 | 记录人工基线，按来源类别比较；不混算未知投递            |
| 重复投递率     | 同一 delivery 因重试产生多次外发的次数                     | 故障注入目标为 0；未知状态不得自动重发                  |
| 状态误报率     | 未检测/不可达/加载失败被显示为健康或空结果的次数           | 验收目标为 0                                            |
| 安全边界回归   | 未授权 IPC、跨空间查询、越界路径、敏感导出测试             | 所有专项负向用例拒绝并保留审计证据                      |

## 10. 范围决策与未决事项

- 本轮必须先修现有体验与可靠性，再增强已有功能闭环；不因“功能看起来不够多”而扩张产品入口。
- M5 项目记忆、共享模板、成果版本和质量/费用分析属于候选能力。其数据来源、共享权限、保留期限和可解释口径未定，不能直接排进 M0–M4。
- 新增社区、复杂工作流/DAG、更多渠道或媒体类型之前，先收集对应用户任务与来源协议；渠道/媒体已有实现不代表本轮需要重做。
- 估算仅为起步容量，不是承诺日期；开工前以实际复现、并行人力、外部账号和 Windows/macOS/Linux 设备可用情况重估。
- 尚缺产品决策时按当前边界执行：不自动发送、不自动重放有副作用运行、不推断旧日期、不删除索引对应文件、不将未检测能力标为健康。需要改变这些边界时单独提出决策记录。
