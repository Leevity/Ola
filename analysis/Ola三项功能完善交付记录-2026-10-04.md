# Ola 三项功能完善交付记录

日期：2026-10-04。范围：当前 M0–M4 的三条开发线，以及 Windows x64 源码 Electron 验证。其他平台不纳入本轮完成条件。

## 1. 结果收集、预览和复用

- SSH Bash 的 outputFiles 已接入：最多 16 个绝对路径，执行前后通过已授权 SFTP 元数据确认变化，成功且未超时才收集，登记前再次确认存在。
- MCP 工具支持原生 resource_link 中的 HTTP/HTTPS 资源，拒绝带用户名密码的 URL 和本地/其他协议 URI；文本中的路径及 URL 不被猜测登记。
- MCP isError=true 作为失败工具结果记录，不登记产物。
- Host 结果提取协议支持远程链接，仍通过统一 artifact.registered 事件和 Run Journal 保存来源。
- 结果中心的链接支持“用作下一次输入”：仅添加文本引用，不自动联网读取；原文本、附件和 Skill 保留，同一链接不重复添加。
- 结果复用在异步检查后复核空间和会话；移除结果索引仍保留源文件。
- 结果页面中英文搜索、复制、重复引用和空态文案覆盖链接。

边界：MCP 本地资源和嵌入内容尚未转为本地文件；独立视频/音频任务尚未整体并入 Run 结果索引。SSH 结果支持已有远程预览/路径复制，自动加入下一次输入目前限本地文件与链接。SFTP 秒级时间戳导致无法确认的同尺寸覆盖不登记。以上仍是后续开发边界，不能写成全部来源已签收。

## 2. 运行状态与失败恢复

- 运行列表可见时每 5 秒刷新，详情执行中每 3 秒刷新，隐藏页面暂停轮询，终态详情停止轮询；详情快照的真实运行状态和审批状态同步回列表。
- 接受取消请求后保持请求态，不立即伪造“已取消”；收到真实终态后解除请求态。等待能力和取消中状态亦覆盖操作呈现。
- 刷新采用按来源/ID 合并，保留用户已加载的列表与结果分页，不因刷新丢掉后续页。
- 失败草稿恢复核对实际 runId、空间和当前仍存在的会话；已有未发送内容不覆盖，切换空间后不跳到旧会话。
- 投递核对和重试的异步响应在切换运行或工作空间后不更新新详情。

边界：普通会话失败恢复仍是原始文本草稿，不自动重放副作用；原始图片由用户重新附加。双窗口运行中删除、复杂审批竞态和真实模型故障由用户手测，本轮未宣称完成这些组合场景的签收。

## 3. 模板、能力诊断与 Cron 反馈

- 项目目录失败可“重新检查目录”，并打开项目目录选择/创建入口；SSH 缺失或检测失败可直达 SSH 管理；模型未配置或最近观测不可用时可打开模型设置。
- 模板未发送的范围和材料按空间、模板与版本临时恢复，关闭后重开及修复导航可继续；仅在内存保留最多 32 份，不将材料写入 localStorage，退出应用后不保留。
- 能力状态说明允许换行；刷新部分失败会明确提示并保留对应配置入口，空间切换后不继续检查旧空间渠道。
- Cron 加载失败保留原列表并呈现错误，恢复刷新后清除错误；较早的加载响应不能覆盖较新的响应。
- Cron 开关、删除和立即运行必须有成功确认；IPC 拒绝有提示，同任务操作去重。切换空间后旧响应不能删除新空间同 ID 记录。
- Cron 启用后的调度状态从 Main 列表读取，不再直接把 enabled 当作 scheduled；立即运行反馈是“已提交执行请求”，不冒充执行成功。

## 用户手测顺序

1. 用真实 MCP 生成一个资源链接：成功时查到来源结果，失败时不出现成功产物；点“用作下一次输入”，原草稿仍在，重复点击不重复引用。
2. 用测试 SSH 命令声明 outputFiles，生成文件后从结果入口预览；失败或超时不登记，路径复制正确。
3. 打开运行详情，执行、等待审批、取消；观察列表和详情是否更新，取消请求与最终取消是否区分；失败恢复已有草稿时是否保留。
4. 填模板材料和范围，关闭重开；再缺模型、目录或 SSH 时跳转修复并返回，检查参数和提示。
5. Cron 禁用/启用、立即运行、删除、刷新；断网/失败时应提示且保留数据，运行请求成功后去记录看实际终态。
6. 能力中心刷新，确认错误原因完整可读并能打开对应设置；真实渠道投递及休眠恢复按 Windows 手测清单执行。
